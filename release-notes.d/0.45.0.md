> [!WARNING]
> **Files that an earlier opossum started may be refused now, a few values are read differently, and some named commands are refused.**
>
> This release holds more of a compose file to what docker compose takes, so some files that 0.44.0 started now stop `up`, `ps` and `config`. The commonest is a date written without quotes (`2024-01-01`) for a key of a service, such as `hostname`, `container_name`, `pull_policy` or `platform`, or for a key or a list item of its `build`: quote it to write it as text. Others are a `healthcheck.test` list that does not start with `NONE`, `CMD` or `CMD-SHELL` (`test: [sh, -c, "true"]`, which is also how 0.44.0's `opossum config` wrote a test back), a `healthcheck.start_interval` that is not text, a word for `healthcheck.retries` or `disable` in a file that another service extends from, a `gpus` entry whose `count` is a word other than `all` or stands beside `device_ids`, a string for `gpus` written over an earlier `gpus`, a `deploy` that is a list in a service an `extends` takes, a `blkio_config` weight that is a string or below zero, a `depends_on` condition that is not one of the three docker compose reads (even where a later file writes a good one over it), a service whose `models` names a model the project does not declare, a key docker compose does not take in a `build.secrets` entry or in a top-level declaration a merge key brings in, and a `mode` of `-0`, a float or a sign after `0o` in a secret or config. Write the value as docker compose reads it (`["CMD", "curl", "-f", "http://localhost"]` or a string for a test, `"10s"`, `10`), rename an unknown key to `x-<key>` to keep it as a note, or declare what is named. A project already running from such a file is taken down by a plain `opossum down`, which says the file is refused and goes on.
>
> Two things are read differently. In a later `-f` file, a mapping or a list tagged `!override` or `!reset` that a service takes in through a merge key (`x-b: &b {<<: !override {labels: {z: '9'}}}`, `s: {<<: *b, image: x}`) now replaces the whole service, or the whole key it is merged into, as docker compose reads it, so the `command`, `working_dir`, `labels` and other keys of the earlier file are gone: write the ones you need inside the tagged value, or drop the tag if you meant to merge. A `!reset` of one name of an `environment`, `labels` or `build.args` no longer takes that name out when the earlier file got the key from two places (a service that `extends` another and writes the key itself, or an `include` beside the including file), as in docker compose.
>
> `stop`, `kill` and `logs` that name a service now refuse a `depends_on` cycle among the services the run reads, whichever service they name; a plain `opossum stop` or `opossum down` still takes the project down. And `up other db` is now refused when `other` has no profile and depends on `db`, whose profile is not on, as `up other` already was: give the profile, as in `opossum --profile g up other`.
