> [!WARNING]
> **Many compose files that docker compose refuses, and that loaded before, are now refused.**
>
> The loader now refuses what docker compose refuses in more places, and each of these loaded on 0.39.0: a string that is not a size or a duration (`stop_grace_period: "10"`, `mem_reservation: "1x"`), a string outside a key's range (`cpu_percent: "150"`, `oom_score_adj: "2000"`, `cpu_count: "-1"`), a `scale` or `deploy.replicas` that is negative, not a whole number or different from the other, a number written as `.inf` or `.nan`, a tag on a value that is not of that type (`!!int abc`, `!!float abc`, `!!int -0`), a mapping key that is not a string (`1: a` in an `x-` block), a `<<` merge key that holds no mapping, an empty name in `sysctls`, a port written as a float, and a long-form port or `deploy.mode` with a value of the wrong kind. The error names the line or key; quote a value you mean as text (`".inf"`, `"1": a`). A project already running on such a file still comes down with a plain `opossum down`, which names the value on stderr and goes on.

> [!WARNING]
> **`down` now asks for the project name when the documents of one file name different projects.**
>
> A compose file of several YAML documents whose later document sets another `name:` than the first is refused by `down`, `destroy`, `stop` and `kill`, because 0.38.0 and later started the project under the later name while earlier versions used the first. Name the one you mean: `opossum -p <name> down`. The error prints both names.
