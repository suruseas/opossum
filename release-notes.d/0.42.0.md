> [!WARNING]
> **A short `volumes` mount with an empty section, which started before, is now refused.**
>
> A short mount with nothing before its first colon (`:/data`, `:/data:ro`, and `${DATA}:/data` when `DATA` is not set) or nothing after its second (`/a:/b:`, `/a:1:`) is refused when the file is read, as docker compose refuses it; before, such a service started with an anonymous volume in place of the missing source. The error names the entry; write the source (or set the variable), or remove the trailing colon. A project already running on such a file still comes down with a plain `opossum down` (with the same `-f` files), which names the entry on stderr and goes on; add `-v` to remove the anonymous volume as well. `ps` and `up` refuse the file until it is fixed.
