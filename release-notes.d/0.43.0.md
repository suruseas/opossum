> [!WARNING]
> **Files that an earlier opossum started may be refused now, and some values are read differently.**
>
> This release reads compose files the way docker compose does in many more places, so a value of the wrong type or shape that used to be passed on or ignored now stops `up`, `ps` and `config`, naming the key and the line: `bind:` options, the blocks of `deploy`, the fields of `build`, a secret's or config's `mode`, `cpus` written with blanks or as `"NaN"`, `host_ip: ""`, a float in `expose`, a key left with nothing after it in a later `-f` file, an extending service or a merge key, a `name:` whose variables come to nothing, a `links:` entry for a service the file does not define, and an escape YAML does not take in a default inside double quotes. A project already running from such a file can still be taken down: a plain `opossum down` goes on for most of them, and where it refuses the file, `opossum -p <name> down` takes it down. A named `stop`, `kill`, `logs` or `start` now also refuses over a broken dependency the run reads, as docker compose does; give the same `--profile` you gave `up`, or use `down`.
>
> Some values are read differently, and the container gets something else. A bare number with a leading zero is octal, as YAML and docker compose read it: `ports: [047103]` publishes port 20035, `cpus: 010` is eight, and `mem_limit: 0600000000` is 96 MB, below what the runtime takes, so that service no longer starts; quote the number or drop the zero to keep the old value. A `!reset` or `!override` inside an anchor is now applied where the anchor is used, so a port, a tmpfs or a variable it resets is gone. `links:` and `network_mode: service:` now set the start order, and `up <service>` brings those services along.
