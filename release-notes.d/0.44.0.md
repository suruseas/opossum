> [!WARNING]
> **Files that an earlier opossum started may be refused now, a few values are read differently, and `up --from-docker` is gone.**
>
> This release holds more of a compose file to what docker compose takes, so some files that 0.43.0 started now stop `up`, `ps` and `config`: a byte size with a space in it or a unit docker compose does not read (`mem_limit: " 1g"`, the `memory` of `deploy.resources`), a `healthcheck.start_interval` that is not a duration (`abc`, or a bare number such as `10`), a `blkio_config` rate that is not a byte size, a key docker compose does not take inside `logging`, `provider`, `credential_spec`, `blkio_config`, a `post_start`, `pre_stop` or `pre_start` hook, a `devices` mapping or a model, a hook with no `command`, a device with no `source`, a `provider` with no `type`, an `extra_hosts` entry with no address (`extra_hosts: [a]`), and a secret's or config's `mode: -0` brought in by a merge key. Write the value as docker compose reads it (`1g`, `10s`, `10mb`, `"0440"`), rename an unknown key to `x-<key>` to keep it as a note, or add the key that is missing. A project already running from such a file is taken down by a plain `opossum down`, which says the file is refused and goes on.
>
> A named `stop` or `kill` is now refused, as docker compose refuses it, when a service outside the active profiles depends on the service it names (by `depends_on`, `links`, `network_mode: service:` or `volumes_from`). Give the same `--profile` you gave `up`, as in `opossum --profile g stop web`.
>
> Two things are read differently. In a later `-f` file, an anchor tagged `!override` or `!reset` that a service takes in through a plain anchor (`x-b: &b {<<: *c}`, `s: {<<: *b}`) now replaces the service as docker compose replaces it, so the `ports`, `labels` and other keys of the earlier file are gone; write the ones you need inside the overriding anchor, or drop the tag if you meant to merge. Where that leaves the service with no `image`, `up` refuses it, and a plain `down` refuses it too: take a project that is already running down with `opossum -p <name> down`, using the file's `name:`. And a `services: !override` over a file brought in by `include` now keeps the included services, so they start with the rest.
>
> `opossum up --from-docker`, the old name of `--from-docker-compose`, was removed: it now refuses and names `--from-docker-compose`, which does what it did.
