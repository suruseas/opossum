> [!WARNING]
> **Some keys written with nothing after them, which loaded before, are now refused.**
>
> A key a later `-f` file writes with nothing after it, where no earlier file gave it a value (`dns:`, `deploy: {mode: ~}`), is refused, and so is such a key inside a service's `deploy`, `build`, `healthcheck`, a `networks` entry or a `depends_on` entry (`deploy: {labels: }`, `build: {network: }`, a network's `aliases:`), as docker compose refuses them. A `cpus` that reads as no number (`cpus: abc`) is now refused in a file that is only extended from too. The error names the key; write the value, or remove the key. A project already running on such a file still comes down with a plain `opossum down` (with the same `-f` files), which names the key on stderr and goes on.

> [!WARNING]
> **`entrypoint: []` now takes the image's own entrypoint away, and a running service that writes it is recreated.**
>
> A service with `entrypoint: []` (or `entrypoint: ""`) used to run the image's ENTRYPOINT with the command after it; it now runs the command alone, as docker compose does. The next `up` recreates such a service even if an earlier version started it. If the service needs the image's entrypoint, remove `entrypoint: []`.
