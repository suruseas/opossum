> [!WARNING]
> **Some compose files and `.env` files that loaded before are now refused, as docker compose refuses them.**
>
> Earlier versions accepted these and went on; this version stops when the file is read, naming the file and the line. A variable name in a `.env` or env file with a space or ASCII punctuation (`A B=1`, `A/B=1`): rename the variable. A secret or config name outside letters, digits, `.`, `_` and `-` (`"my s"`): rename it. A short mount with nothing after the colon (`./src:`): write the target (`./src:/app`). A long-form mount whose `target` is a number, a boolean or a date (`target: 5`): write the path as text. A key written twice in the same mapping inside an `x-` extension: keep one.
>
> A project already running on such a file can still be taken down: `down`, `destroy`, `stop` and `kill` go on for the `.env` and name cases, and `opossum -p <name> down` takes a project down by its label when its file is refused.

> [!WARNING]
> **Two readings now follow docker compose and can change what a service gets without an error.**
>
> `build.dockerfile` is read from the build context: with `context: ./sub`, write `dockerfile: Dockerfile.alt`, not `sub/Dockerfile.alt`. A `${...}` in a key under `environment:` or `labels:` is no longer expanded: `E${SFX}: "1"` sets a variable named `E${SFX}`; values are expanded as before. A label written as a mapping with a number, boolean or date value (`a: 0x10`) now carries docker compose's value (`16`), so its service is recreated by the next `up`.
