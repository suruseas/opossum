> [!WARNING]
> **Some compose files that loaded before are now refused, as docker compose refuses them.**
>
> A key written twice in one mapping is refused wherever it is, including `logging`, `sysctls`, `ulimits`, `extra_hosts` and a network's `driver_opts`: keep one (in `ulimits` the second value used to win). A service key opossum does not act on now has to have the shape docker compose gives it (`hostname: [1, 2]`, `dns: 7`, `privileged: 7`, `container_name: x`): write it as docker compose takes it, or remove it. A file that ends in `---`, or has two `---` in a row, is refused: remove the empty document. A network `name:` the container runtime cannot create (upper case, `+`, more than 63 characters) is now refused by `up` and `run`: use lower case letters, digits, `.`, `_` and `-`. A project brought up by an earlier version with `networks: {default: {internal: true}}` is refused by `up` with `[OPSM-207]` until it is taken down once.
>
> A project already running on such a file can still be taken down. Where the file itself is refused, `down` refuses too: take the project down by its name, `opossum -p <name> down`. For the two network cases, `down` goes on as before.

> [!WARNING]
> **Three readings now follow docker compose and change what a service gets without an error.**
>
> A file with several YAML documents is read whole: each document is merged into the ones before it, so a service defined after a `---`, which used to be dropped, now starts. A network with a `name:` of its own is created under that name instead of `<project>-<key>`, and the next `up` recreates its services on it. The `default` network is one network: a service that lists `default` moves from `<project>-default` to `<project>-net`, and `default: {internal: true}` now applies to services that list no networks, so after a `down` and `up` they are host-only.
