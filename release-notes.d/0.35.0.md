> [!WARNING]
> **A key under a bind mount's `bind:` that docker compose does not take now stops the file from loading.**
>
> Earlier versions never read what was under `bind:`, so a misplaced or misspelled option — `bind: {subpath: sub}`, whose `subpath` belongs under `volume:`, or `bind: {propogation: rprivate}` — loaded and started with the option doing nothing. It is now refused, naming the key, as docker compose refuses that file. Remove the key or correct its spelling; the four options docker compose takes there — `propagation`, `create_host_path`, `selinux`, `recursive` — are accepted as before.
